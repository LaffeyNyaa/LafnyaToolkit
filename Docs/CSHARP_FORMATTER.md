# C# 格式化工具

## 概述

- **位置**：该工具位于 `CSharpFormatter` 目录中。
- **参数**：接受一个目录路径作为参数，递归格式化该目录及其子目录中的所有 `.cs` 文件。
- **验证**：如果未提供参数或指定目录不存在，工具将输出错误信息并以退出码 2 终止。
- **执行输出**：实时显示文件处理状态，标明正在格式化或已跳过。
- **跳过逻辑**：如果格式化后的内容与原始文件完全相同，则该文件被视为"已跳过"。
- **汇总**：完成后输出统计信息，包括文件总数、已格式化数、已跳过数和失败数。
- **输出编码**：文件始终以无 BOM 的 UTF-8 编码写入。
- **原子写入**：通过 `File.Replace` 实现原子写入，在不支持时回退为 `Delete` + `Move`。

## 格式规则

### 大括号风格（Allman）

所有左大括号 `{` 必须放在单独的行上（Allman 风格）。位于行尾的左大括号会被移动到新行。

- **错误示例**：
  ```csharp
  if (a == b) {
      return true;
  }
  ```
- **正确示例**：
  ```csharp
  if (a == b)
  {
      return true;
  }
  ```

此规则适用于所有构造：`if`、`else`、`for`、`foreach`、`while`、`do`、`switch`、`try`、`catch`、`finally`、`lock`、`using`、`fixed`、`checked`、`unchecked`、方法、属性、类、结构体、接口、枚举和命名空间。

此规则仅移动代码区域（Code token）中的大括号。字符串字面量、原义字符串、注释和插值字符串中的大括号保持不变。

### 强制大括号

所有控制流语句必须使用花括号。单语句体将自动包裹在 `{...}` 中。

强制要求大括号的关键字包括：`if`、`else`、`for`、`foreach`、`while`、`do`、`lock`、`using`、`fixed`、`checked`、`unchecked`。

- **错误示例**：
  ```csharp
  if (a == b) return true;
  ```
- **正确示例**：
  ```csharp
  if (a == b)
  {
      return true;
  }
  ```

- **错误示例**：
  ```csharp
  for (int i = 0; i < 10; i++)
      Process(i);
  ```
- **正确示例**：
  ```csharp
  for (int i = 0; i < 10; i++)
  {
      Process(i);
  }
  ```

大括号插入在词法分析阶段进行，通过 Token 序列操作实现，确保仅处理代码区域中的关键字。

### 缩进

- **缩进大小**：每级缩进使用恰好 **4 个空格**。
- **Tab 替换**：代码区域（Code token）中的 Tab 字符被替换为 4 个空格。字符串字面量、原义字符串（`@""`）和注释中的 Tab 保持不变。

#### 基于大括号嵌套的缩进

缩进深度通过扫描代码区域中的 `{` 和 `}` 计算得出。每遇到一个 `{`，深度加 1；每遇到一个 `}`，深度减 1。

#### 续行缩进

以续行指示符结尾的行，其后续行将额外缩进一级。续行指示符包括：
`,`、`+`、`-`、`*`、`/`、`%`、`(`、`=`、`?`、`<`、`>`、`&&`、`||`

#### Switch/Case 缩进

`switch` 块内的 `case` 和 `default` 标签相对于 `switch` 关键字缩进一级。每个 case 的代码体与 case 标签处于同级缩进，不额外缩进。

- **示例**：
  ```csharp
  switch (x)
  {
      case 1:
          DoSomething();
          break;
      default:
          break;
  }
  ```

#### 原义字符串与多行注释的缩进保护

完全位于原义字符串（`@""`）或多行注释（`/* */`）中的行，其原始前导空白保留不变，不会被重新缩进。

### 行长度限制

- **最大长度**：每行代码不得超过 **80 个字符**。
- **换行规则**：超过 80 个字符的语句必须拆分为多行。
- **安全断点**：行拆分在以下安全断点处进行：`,`、`;`、`=`、`==`、`!=`、`<`、`<=`、`>`、`>=`、`+`、`-`、`*`、`/`、`%`、`&&`、`||` 以及复合赋值运算符（`+=`、`-=` 等）。
- **续行缩进**：续行比语句基础缩进多一级。
- **续行之续行**：如果续行本身因超长再次被拆分，其所有段的缩进保持与该续行相同（不会进一步级联加深）。

#### `++` 和 `--` 运算符保护

`++` 和 `--` 运算符被视为原子单元，不允许在其中间断行。

### 空行：代码块与多行语句

- **通用规则**：在代码块和多行语句的上方和下方保留恰好一个空行。
- **例外**：
  - 如果块位于父块的最开头，则上方不添加空行。
  - 如果块位于父块的最末尾，则下方不添加空行。
- **多行语句检测**：
  - **多行语句结束**：以 `;` 或 `}` 结尾且前一行是续行（以续行指示符结尾）的行被视为多行语句结束，在其下方添加空行。
  - **多行语句开始**：以续行指示符结尾且前一行不是续行的行被视为多行语句开始，在其上方添加空行。
- **错误示例**：
  ```csharp
  int i = 0;
  for (int i = 0; i < 10; i++)
  {
      Console.WriteLine(i);
      if (i == 5)
      {
          Console.WriteLine("i is 5");
      }
  }
  ```
- **正确示例**：
  ```csharp
  int i = 0;

  for (int i = 0; i < 10; i++)
  {
      Console.WriteLine(i);

      if (i == 5)
      {
          Console.WriteLine("i is 5");
      }
  }
  ```

### 空行：try/catch/finally 抑制

`catch` 和 `finally` 关键字直接跟在前面代码块的闭花括号之后，两者之间不插入空行。此规则覆盖块结束规则和多行规则。

- **正确示例**：
  ```csharp
  try
  {
      ProcessData();
  }
  catch (Exception ex)
  {
      LogError(ex);
  }
  finally
  {
      Cleanup();
  }
  ```

### 空行：if/else 抑制

`else` 关键字直接跟在前面 `if` 代码块的闭花括号之后，两者之间不插入空行。此规则覆盖块结束规则和块开始规则。

- **正确示例**：
  ```csharp
  if (condition)
  {
      DoSomething();
  }
  else
  {
      DoSomethingElse();
  }
  ```

### 空行：文档注释

- **通用规则**：当上一行非空行为代码语句时，在文档注释块（`///`）上方保留恰好一个空行。这使"文档注释 + 声明"逻辑单元与前一个单元分隔开。
- **例外**（不在 `///` 上方添加空行）：
  - 上一行非空行本身是 `///` 文档注释（多行文档续行）。
  - 上一行非空行是常规注释（`//`、`/*` 或 `*` 续行），附加到下面的声明上。
  - 上一行非空行是块开始大括号（单独的 `{` 或以 `{` 结尾的行）。
- **错误示例**：
  ```csharp
  /// <summary>Indentation uses 4 spaces per level.</summary>
  private const int IndentSize = 4;
  /// <summary>Maximum length of a single line.</summary>
  private const int MaxLineLength = 80;
  ```
- **正确示例**：
  ```csharp
  /// <summary>Indentation uses 4 spaces per level.</summary>
  private const int IndentSize = 4;

  /// <summary>Maximum length of a single line.</summary>
  private const int MaxLineLength = 80;
  ```

### 保留单行语句之间的作者空行

在所有其他空行规则决定在当前行上方不插入空行后，此回退规则保留作者在相邻单行语句之间插入的空行。

- **仅保留**：此规则仅保留已有的空行（基于原始输入中当前行上方是否有空行），不会在作者未放置空行的地方插入新空行。
- **幂等**：由于此规则仅保留已有空行而从不引入新空行，重复运行格式化器将产生相同输出。
- **"单行语句"的定义**：当以下所有条件成立时，一行被视为单行语句：
  - 行的起始在代码区域中。
  - 修剪后的行以 `;` 或 `}` 结尾（语句结束）。
  - 该行不是块结束行（不是 `}` 或 `};`）。
  - 该行不是块开始行。
  - 该行不是注释行。
- **示例**：
  ```csharp
  int[] lineStarts = new int[10];

  List<int> enumRanges = new List<int>();
  int depth = 0;
  int enumDepth = -1;
  int enumStart = -1;
  bool pendingEnum = false;

  for (int i = 0; i < 10; i++)
  {
  ```
  `lineStarts` 和 `enumRanges` 之间的空行被保留。`enumRanges`/`depth`/`enumDepth`/`enumStart`/`pendingEnum` 之间不插入空行，因为原始输入中没有空行。

### 多余空行折叠

连续 2 个及以上的空行被折叠为 1 个。

### 行尾空白修剪

所有行的尾部空白被去除。

### 文件末尾换行

每个文件必须以恰好一个换行符结尾。如果此规则与其他间距规则冲突，文件末尾换行符具有绝对优先权。

### Using 指令排序

`using` 指令被分为四个组，并按以下严格顺序排列：

1. **System 命名空间**（以 `System` 开头的命名空间）
2. **第三方库**（不属于其他组的命名空间）
3. **同一项目的其他模块**（以当前模块根命名空间 + `.` 开头的命名空间，但不等于当前模块）
4. **当前模块**（与文件所属模块的根命名空间完全匹配）

每组之间用恰好一个空行分隔。组内按命名空间的字典序（Ordinal 比较）排序，命名空间相同时按完整指令文本排序。

#### 根命名空间解析

当前模块的根命名空间通过以下方式解析：
1. 从文件目录向上遍历，查找第一个 `.csproj` 文件。
2. 从 `.csproj` 文件中读取 `<RootNamespace>` 元素的值。
3. 如果未找到 `.csproj` 文件或 `<RootNamespace>` 元素缺失，则回退为目标根目录的目录名。

- **示例**（假设根命名空间为 `MyApp`）：
  ```csharp
  using System;
  using System.Collections.Generic;

  using Newtonsoft.Json;
  using NUnit.Framework;

  using MyApp.Common;

  using MyApp.Services;
  ```

### 枚举声明

单行枚举声明会被展开为多行形式，每个成员占一行，最后一个成员带尾随逗号。

- **错误示例**：
  ```csharp
  enum TokenType { Code, String, VerbatimString, Char, SingleLineComment, MultiLineComment }
  ```
- **正确示例**：
  ```csharp
  enum TokenType
  {
      Code,
      String,
      VerbatimString,
      Char,
      SingleLineComment,
      MultiLineComment,
  }
  ```

仅当枚举体为单行（不包含换行符）时才会展开。已有的多行枚举保持不变。

### 属性访问器展开

单行属性访问器块（如 `get { return x; }`）会被展开为多行形式。支持嵌套访问器块的递归展开。

- **错误示例**：
  ```csharp
  public int Value { get { return _value; } set { _value = value; } }
  ```
- **正确示例**：
  ```csharp
  public int Value
  {
      get
      {
          return _value;
      }
      set
      {
          _value = value;
      }
  }
  ```

仅当块内容由访问器关键字（`get`、`set`、`init`、`add`、`remove`）组成时才执行展开。仅包含 `;` 的访问器（如表达式体成员）保持单行。

### Token 感知处理

所有结构化格式化操作（大括号放置、大括号强制、缩进、续行检测、空行规则、行长度拆分）都是 **token 感知**的。格式化器在应用任何结构化变更之前，将源码分词为以下 token 类型：

- **Code** — 普通代码（标识符、关键字、运算符、标点等）
- **String** — 常规字符串字面量 `"..."`（含转义序列）
- **VerbatimString** — 原义字符串 `@"..."`（`""` 表示嵌入引号）
- **Char** — 字符字面量 `'...'`（含转义序列）
- **SingleLineComment** — 单行注释 `//...` 到行尾
- **MultiLineComment** — 多行注释 `/* ... */`
- **Preprocessor** — 预处理器指令 `#` 开头至行尾（含反斜杠续行）

#### 受保护内容

- **注释**：`//`、`/* */` 和 `///` 文档注释中的内容永不被修改。大括号、关键字和制表符在注释中保持不变。
- **字符串字面量**：`"..."` 中的内容永不被修改。
- **原义字符串**：`@"..."` 中的内容永不被修改。原义字符串中的 Tab 被保留。
- **预处理器指令**：`#` 开头的预处理器行保持完整。

### 幂等性

格式化是**幂等**的：对已格式化的文件运行格式化器不会产生任何变化。一次格式化即可达到最终状态——重复运行将始终产生"已跳过"状态，修改数为零。

此保证适用于流水线中的所有转换：大括号强制、Allman 大括号放置、枚举展开、属性访问器展开、using 排序、Tab 替换、缩进、空行规则、多余空行折叠、行尾空白去除和行长度拆分。

### 错误处理

如果在处理文件时发生错误（如只读、被锁定、权限不足），工具将向标准错误输出打印 `Error: <relative path>: <message>`，递增失败计数，然后继续处理其余文件。单个文件失败不会中止整个运行。

### 文件 I/O 行为

- **读取编码**：格式化器通过字节顺序标记（BOM）自动检测文件编码。支持的编码：UTF-8（带/不带 BOM）、UTF-16 LE（带 BOM）、UTF-16 BE（带 BOM）、UTF-32 LE（带 BOM）、UTF-32 BE（带 BOM）。无 BOM 的文件按 UTF-8 读取。
- **写入编码**：格式化后，文件始终以无 BOM 的 UTF-8 编码写入，无论原始编码如何。如果格式化内容与原始内容相同（且原始内容已为无 BOM 的 UTF-8），则文件被跳过，不重新写入。
- **原子写入**：输出先写入同一目录的临时文件，然后通过 `File.Replace` 原子交换到位（在不支持 `File.Replace` 时回退为 `Delete` + `Move`）。写入失败不会损坏原始文件。
- **逐文件弹性**：如果单个文件的读取或写入引发异常，工具将打印错误信息（包含文件名）并继续处理其余文件。
- **退出码**：进程退出码等于失败文件数（0 表示所有文件处理成功）。
- **汇总行格式**：`Total: N, Formatted: F, Skipped: S, Failed: W`
